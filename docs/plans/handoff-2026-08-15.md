## What shipped today

### The email localisation epic (#36) — all three steps

**One body per template** (`b5d937e`). `backend/emails/`: `render.py` turns a
block list into text and HTML, `catalog.py` says which blocks each of the ten
messages has, `strings/<lang>.json` holds every word. Markup is deliberately
three things — `**bold**`, `` `code` ``, `[label](url)`. Variables are
`${name}` (string.Template) because the welcome email contains the literal
merge tag `{{firstName}}`, which under `.format` would need `{{{{firstName}}}}`
in fourteen files.

The goldens pin bytes and bytes had to move, so the real check was a
**word-level diff** of old golden against new render: **7 of 10 templates came
out word-identical in every part.** The three differences were all the same
thing — the text and HTML halves had silently drifted and one had to win.
**Five templates gained a `text/plain` part** they never had.

**The language travels** (`7e7c8d8`). One header, `X-UI-Language`, beside the
`X-Extension-Version` header that already rode there. Stored via
`maybe_touch_activity` on the changed-value path. The service worker cannot
call `getActiveLocale()`, so `_uiLanguageTag()` mirrors it — and
`extension/tests/ui-language-header.test.js` runs both against the same eight
inputs in a vm and requires the same answer.

**Thirteen translations** (`577262a`). 89 keys each, covering all fourteen
panel locales (zh_CN → zh; zh_HK/zh_MO aliased to zh_TW so they do not fall
back onto the wrong script).

### What the translation review found — mostly in our own code

A 37-agent adversarial review (12 native-level reviewers, 2 skeptics each,
one synthesis) produced 133 claims, **78 survived**. The two worst were not
translations (`9294183`):

* **`f"{n:,}"` is English.** In German, Turkish, Spanish and both Portuguese
  the comma is the DECIMAL separator, so the upgrade email told a new Pro
  customer they could send **ten** emails. Seven of twelve languages wrong.
  The separator now lives in the string table as `common.number_group`.
* **The day was zero-padded** — "on September 05", in all thirteen languages
  including English, inherited from `strftime("%B %d")`.
* **The English source quoted a button that does not exist.**
  `quota_capped.sooner` said click **Upgrade**; the English panel button is
  **Upgrade Plan**. Twelve translators faithfully translated a wrong label,
  which is why ten of them were reported as translation errors.

`tests/test_email_quotes_real_labels.py` now maps each email string that names
a control to the panel keys it names. **English is strict.** The translations
carry an allowlist of the **23** mismatches that exist today, which may only
shrink; a second test fails when an entry becomes stale.

### The panel showed a plan the server had stopped agreeing with

`a2e13df`. Compose bar read "250/250 (Pro Plan)" while the Account tab read
"Free", on the same panel, at the same instant. Four links, all four true:

1. The write was not atomic — count always, plan only if changed, limit only
   if truthy, and `result.plan` read **before** the network round trip.
2. The login write set `plan` and neither sibling — also a cross-account leak
   of the sent count on "Change account".
3. `loadQuota` discarded the one internally-consistent answer it was handed
   and re-read a cache, on an ordering MV3 does not guarantee.
4. `storage.onChanged` did not repaint, so a bad paint was frozen for the life
   of the panel.

Also: the Account tab's static placeholders were `Free` and `0`, and
`loadAccount` returns early on failure without clearing them — a failed load
rendered pixel-identically to a real free account. They are `-` now.

**The mirror case cost money** (`ec0d751`, approved by Ali). The pre-send
guard read the same cache and hard-blocked. A Pro customer whose cache said
"free" was stopped at 250 **client-side, before the request left the browser**
— and the population most likely to hit it is the one that just paid. It now
blocks only on a live `/settings` answer. The backend enforces quota anyway.

### A paid month starts when it is paid for

`28a8c75` + migration 031. `check_monthly_reset` compares DATES from the beat,
so it fired minutes after 00:00 UTC; Stripe charges at the subscription's
creation TIME — 20:20 UTC for bellmed. Twenty hours of unpaid quota, every
month, for every subscriber.

Not fixed by computing the moment more precisely — by **not computing it**.
`invoice.payment_succeeded` with `billing_reason == "subscription_cycle"` now
rolls the quota, delegating to the same `check_monthly_reset` with a flag that
lifts its hold. Idempotent by construction. The date anchor stays as a bounded
one-day backstop, and remains the whole rule for free users and manual promo
grants (migration 026 already clears `stripe_subscription_id` when granting).

### The green check (`89c00e9` → `49697e2`)

`workers/green_report.py`, sent to Telegram daily at **07:00 UTC**, and
runnable on demand **in production**:

```
/opt/venv/bin/python -m workers.green_report
```

That path is measured, not guessed. Bare `python` in a Railway shell is the
system interpreter and fails on `import dotenv`; `command -v uvicorn` finds
nothing either, because the venv is not on that shell's PATH at all.

One builder, two front-ends (`as_telegram` drops the prose, `as_text` keeps
it), so the phone and the terminal cannot disagree. **Zero rows raises** and
sends a red alert naming the likeliest cause first — an anon `SUPABASE_KEY`,
where RLS answers with an empty set and no error.

**Gate 1 answered the day's biggest question: the WEB service carries a live
key against the production database.** No fictional billing state has been
written. The April incident has not recurred.

## What today taught

The same shape, six times, and four of them were in work done this session.

- The **sender detector** written yesterday matched nothing and passed clean.
- A **correlated subquery** reported "0 users came back" for a version a month
  old — impossible, which is the only reason it was caught.
- The **green check's first run** read an empty users table and printed
  "0 accounts, ok" for every line.
- A **sed script** meant to fix two tests printed "patched" while matching
  nothing.
- The **version spread** was read as churn (the measure said nearly four times
  as many were active), then as an Edge-store lag (Edge users were on 0.2.0
  too, and Chrome had the same tail).
- **#48 idea 2** was called unshipped from the `consent_declined` branch, one
  line above the `msCode` test that takes precedence.

Three instructions for running one command in a Railway shell were also wrong
in a row — `cd` into a directory that is not there, an interpreter that is not
the one running, a discovery trick that finds nothing. Each was a statement
about a machine nobody had asked.

The habit that keeps paying: **check the thing whose failure would be silent,
especially when you wrote it — and when a result is zero, ask what a broken
version of the check would have returned.** Usually zero.
